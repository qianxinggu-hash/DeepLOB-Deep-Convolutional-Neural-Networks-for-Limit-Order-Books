## 1. “一条条数据”的学名

这里实际有两种逐事件数据：

- CSV 是 **Market-by-Order（MBO，逐笔委托/订单级事件流）**。核心消息是新增订单、修改
  剩余数量、删除订单和成交打印。要恢复盘口，需要维护 `OrderID -> (方向, 价格, 剩余数量)`，
  再把订单聚合到价格档位。
- 新增的 `.npz` 是 **Market-by-Price（MBP，也叫 L2/逐档行情事件流）**。报价事件直接给出
  某一方向、某一价格的**最新聚合数量**，因此采用“覆盖”而不是“增量相加”。

把这些事件按时间依次应用到内存状态，称为 **订单簿重建（order-book reconstruction）**，
也可以叫 **事件回放（event replay / event-sourced reconstruction）**。

本实验用 CSV 统计每日成交量，用同日 MBP/L2 事件恢复模型输入。选择 MBP 的原因不是省事，
而是它的绝对数量更新具有自愈性：即使早先漏掉一条订单事件，后续该价格的绝对更新仍能把
聚合深度纠正回来。MBO 如果漏掉一条删除或修改，错误订单可能一直残留，除非有可靠的全量
快照重新同步。

## 3. 从逐笔 L2 事件恢复十档盘口

### 3.1 事件语义

| 事件代码 | 含义 | 对盘口状态的处理 |
|---|---|---|
| `0xD0000001` | 卖方绝对档位更新 | 将该卖价聚合数量覆盖为 `qty`；`qty=0` 删除价位 |
| `0xE0000001` | 买方绝对档位更新 | 将该买价聚合数量覆盖为 `qty`；`qty=0` 删除价位 |
| `0xD0000002` | 卖方成交事件 | 只作成交记录，不再次修改静态深度 |
| `0xE0000002` | 买方成交事件 | 只作成交记录，不再次修改静态深度 |
| `0xC0000003` | 清空/重新同步 | 同时清空买卖两侧，并开始新连续片段 |

0807 共1,523,554条 L2 事件：653,956条卖方档位更新、717,009条买方档位更新、
152,588条成交事件和1条 `CLEAR`。

### 3.2 状态机

内存中维护两个 `价格 -> 聚合数量` 映射。价格先转换为千分之一港元整数，例如29.22港元
存为29220，避免浮点数作为键造成同一价格被拆成两个档位。

按如下顺序回放：

```text
依源文件顺序回放，并检查 exch_ts 单调（若倒序则停止）
按“交易所时间的同一毫秒”分组：
    依原顺序应用组内全部事件
    CLEAR       -> 清空两侧并开启新片段
    LEVEL(q>0)  -> 覆盖该方向、该价格的聚合数量
    LEVEL(q=0)  -> 删除该方向、该价格
    EXECUTION   -> 不再扣减静态深度

    若该毫秒位于 09:30-12:00 或 13:00-16:00，且盘口发生变化：
        连续变化毫秒组计数加1
        每10组尝试采样一次
        两侧不足10档 -> 跳过
        best_bid >= best_ask -> 跳过，但绝不猜测性删除订单
        否则输出 ask1/size, bid1/size, ... ask10/size, bid10/size
```

相同毫秒必须作为原子组处理。若在一组中间采样，可能正好看到“旧卖价已经删除、新卖价尚未
加入”的瞬态假盘口。成交事件不能重复扣减，因为绝对档位事件已经表达成交后的剩余深度；
否则会把同一成交计算两次。

盘前事件用于建立09:30开盘时的状态，但盘前不输出训练快照。午间 `CLEAR` 会切断片段；
任何100步输入窗口和未来标签都不能跨过该边界。

实现见 [`lob_reconstruction.py`](lob_reconstruction.py)。重建缓存为
[`data/hk07709_2026-08-07_l2_s10.npz`](data/hk07709_2026-08-07_l2_s10.npz)。

## 4. 可能遇到的异常及规避方法

| 异常 | 风险 | 本次处理 |
|---|---|---|
| 时间戳倒序 | 状态回放因果顺序不确定 | 发现任一倒序立即停止，不擅自排序同时间内部顺序 |
| 相同毫秒多条消息 | 组中间可能短暂交叉或缺档 | 同毫秒全部应用完才允许采样 |
| 未知事件代码 | 可能把快照、状态切换误当普通更新 | 发现未知代码立即停止并要求补充语义 |
| `CLEAR`/重新同步 | 清空前后的状态不可连续 | 清空双方、重置采样片段，窗口和标签不跨片段 |
| 绝对数量被误当增量 | 深度会不断累加并爆炸 | LEVEL 始终覆盖；零数量删除 |
| 成交被重复扣减 | 档位数量被扣两次 | EXECUTION 不修改静态盘口，由绝对LEVEL更新负责余量 |
| 不足十档 | 用0填充会制造不存在的价位 | 跳过该采样点，本次仅2次 |
| 交叉/锁定盘口 | 可能是组内瞬态、缺包或状态错误 | 跳过观察值但不修改状态；本次最终输出为0次 |
| 价格浮点键误差 | 相同价格可能被拆档 | 价格转成千分之一港元整数后作键 |
| 负价格/负数量 | 不符合盘口定义 | 立即报错；零数量只表示删档 |
| 盘前、午休、收盘后消息 | 混入不同市场阶段 | 可用于建立状态，但只在两段连续交易时段采样 |
| 跨午休窗口/标签 | 把不连续市场状态当连续序列 | 保存 `segments`，输入和标签都限制在同一片段 |
| MBO重复新增同一OrderID | 旧订单可能被静默覆盖 | 若走MBO，应标为错误并等待重同步，不直接覆盖 |
| MBO修改/删除不存在OrderID | 表示缺包、重同步缺失或起始状态不完整 | 计数并隔离；不能靠猜测删除另一侧订单来“修好” |
| 证券代码或字段结构漂移 | 可能混入其他股票或错误解析 | CSV审计验证字段和SecurityId；本次无格式无效行 |

### 4.1 旧逻辑为什么危险

旧 [`prepare_hkex_lob.py`](../prepare_hkex_lob.py) 从MBO维护每个OrderID。在盘口交叉时，
它把“最后变化的一侧”当作主动侧，然后删除被穿过价格上的所有被动订单。这个规则无法从数据
证明那些订单一定过期：也可能是消息同毫秒尚未处理完、缺少重同步、市场阶段切换，或者最后
变化的一侧根本不是造成异常的一侧。

旧0807结果记录了77次这种修补，共主动删除5,360个订单；同时存在4,282次删除未知订单和
624次修改未知订单。修补会改变之后所有价位和数量，错误可能持续到收盘。

新方法使用绝对档位更新及显式 `CLEAR`，不猜哪一侧“应该被删”。最终61,677个输出状态：

- 所有值有限；
- 买价逐档严格下降，卖价逐档严格上升；
- 所有静态数量为正；
- `best_bid < best_ask` 全部成立；
- 时间严格递增，两个片段各自连续。

这能证明新输出满足静态盘口约束，但不能证明交易所源数据从未缺包；若要达到生产级，还需要
与官方全量快照、序列号或独立行情源定期对账。

## 5. 70/30时间切分、特征和标签

### 5.1 切分

- 共61,677个快照，按时间位置70%/30%切分；不是随机洗牌。
- 切点：快照43,173，即 **2026-08-07 13:46:16.839（香港时间）**。
- 训练标签最后时刻：13:46:11.457；其未来20步仍全部在切点前。
- 测试第一标签时刻：13:47:00.478；它的100步输入从切点后开始。
- 训练与测试输入共享快照数为0，标签的过去/未来均不跨切点或 `CLEAR`。

最终训练目标42,935个，测试目标18,385个。虽然窗口之间仍高度重叠，但不会发生训练/测试
边界泄漏。

### 5.2 DeepLOB输入

每个样本是最近100个十档状态，形状为 `1 × 100 × 40`。为减小单日价格趋势和长尾数量的
影响，先做：

- 价格：`(档位价格 / 当前中间价 - 1) × 10000`，单位为基点；
- 数量：`log1p(聚合数量)`；
- 然后逐特征z-score，均值和标准差只用前70%快照拟合。

### 5.3 标签

预先固定 `k=20`。对目标时刻 `t`，分别计算同一片段内过去20个中间价（含当前）均值和
未来20个中间价均值：

```text
r_t = mean(mid[t+1], ..., mid[t+20]) / mean(mid[t-19], ..., mid[t]) - 1
```

阈值 `alpha=0.00040587634` 只用训练目标的 `abs(r_t)` 三分之一分位数拟合，使训练平稳类
约占三分之一。测试标签使用同一阈值，不能按测试分布重新调整。

## 6. DeepLOB训练与测试结果

- 架构：仓库现有 DeepLOB（卷积 + Inception + LSTM）；
- 优化器：Adam，学习率 `1e-3`，weight decay `1e-5`；
- 损失：按训练标签频数计算的加权交叉熵；
- batch 256，随机种子42；
- 固定训练12轮，不使用测试集选择轮数或阈值。

### 6.1 总体指标

| 模型/基线 | Accuracy | Balanced Accuracy | Macro-F1 |
|---|---:|---:|---:|
| **DeepLOB** | **33.43%** | **32.52%** | **32.37%** |
| 恒预测平稳 | 41.60% | 33.33% | 19.59% |
| 按训练多数类恒预测下跌 | 24.69% | 33.33% | 13.20% |
| 均匀随机的期望值 | 33.33% | 33.33% | — |

DeepLOB 的 Macro-F1 高于恒定分类器，因为它确实预测了三个类别；但 Balanced Accuracy 比
均匀随机期望还低0.82个百分点，Accuracy 比恒预测平稳低8.17个百分点。不能据此声称模型
具有稳定可交易预测力。

## 9. 仍需注意的限制

1. 单日70/30只能测日内后段泛化，不能替代按连续交易日划分的验证和测试。
2. 18,385个测试窗口高度重叠，有效独立样本数远小于18,385；不应套用独立同分布假设计算
   过度乐观的显著性。
3. 没有独立验证日；12轮是预先固定设置，未做可靠超参数选择。
4. 分类结果没有加入手续费、点差、排队成交概率、延迟、滑点或市场冲击。
5. MBP能规避大量MBO缺包累积问题，但生产级恢复仍应使用官方序列号和周期性全量快照校验。
6. 下一步若研究“天数不连续”影响，应该收集一段连续交易日，按完整日期做
   `train days / validation day / final test day`，不能随机混合日期或窗口。

## 10. 针对“接近随机和严重过拟合”的改进

### 10.1 问题定位

初版的训练 Macro-F1 从48.40%一路升到94.01%，但从未在前70%内部检查时间泛化，直到
12轮结束才看后30%。此外，每个快照的价格都按该快照自身中间价居中，盘口形状被保留，
但100步输入中的绝对价格路径几乎被抹掉；而标签恰好与过去/未来中间价路径有关。

改进实验把前70%称为开发区，在内部再按时间切成：

- 内部拟合：开发区前75%，截至11:37:17.764；
- 内部验证：开发区后25%，截至外层切点13:46:16.839；
- 最终测试：仍为原来的后30%，测试输入不与开发区共享快照。

内部验证只用于选择方案，依次做了：

1. 在 `k=20/50/100` 和逻辑回归 `C=0.01/0.1/1.0` 中选择标签 horizon 和正则强度；
2. 比较带强正则的纯 DeepLOB 与带25维因果特征的混合 DeepLOB；
3. 用验证 Macro-F1 早停并选择训练轮数；
4. 用验证段选择神经网络/逻辑模型融合权重和固定平稳偏置；
5. 固定配置后，从头在完整前70%训练，再评估后30%。

标签 horizon 的内部验证结果：

| Horizon | 最佳验证 Macro-F1 |
|---:|---:|
| **20** | **59.24%** |
| 50 | 56.05% |
| 100 | 58.84% |

因此保留 `k=20`。模型内部验证对比进一步显示：

| 候选 | 最佳轮数 | 验证 Macro-F1 |
|---|---:|---:|
| 仅正则化 DeepLOB | 1 | 35.94% |
| 因果混合 DeepLOB | 1 | 49.48% |
| 25维因果逻辑回归 | — | 59.24% |

两个 DeepLOB 都在第1轮以后验证表现下降，证明旧版12轮训练确实严重过拟合。修复后的训练
协议使用：dropout 0.40、AdamW、weight decay `1e-4`、label smoothing 0.03、梯度裁剪5，
并由验证选择第1轮，而不是继续追逐训练准确率。

### 10.2 新增的25维因果特征

所有特征只使用目标时刻及其过去，不含未来信息：

- 1/2/5/10/20/50/100步中间价收益；
- 当前价格相对过去5/20/50步均价的位置；
- 当前相对价差；
- 买卖1/2/3/5/10档累计深度不平衡；
- 前5档逐档排队不平衡；
- 买卖侧相邻档位价格间距；
- 买卖十档总深度的 `log1p`。

混合 DeepLOB 将卷积/Inception/LSTM 得到的64维盘口表示与这些特征的32维非线性表示拼接，
再做三分类。该分支补回了初版逐行居中时丢失的短期价格路径信息。

### 10.3 改进后的冻结测试结果

| 模型/基线 | Accuracy | Balanced Accuracy | Macro-F1 |
|---|---:|---:|---:|
| 初版 DeepLOB（12轮） | 33.43% | 32.52% | 32.37% |
| 恒预测平稳 | 41.60% | 33.33% | 19.59% |
| **因果混合 DeepLOB（验证早停1轮）** | **48.01%** | **50.18%** | **48.26%** |
| **25维因果逻辑回归** | **60.63%** | **60.57%** | **60.94%** |

相对初版，改进 DeepLOB 的 Accuracy、Balanced Accuracy、Macro-F1 分别提高
**14.58、17.66、15.88个百分点**；Accuracy 也比恒预测平稳高6.41个百分点，原来的
“不如恒预测平稳”问题已经解决。

改进 DeepLOB 的三类结果：

| 类别 | Precision | Recall | F1 |
|---|---:|---:|---:|
| 下跌 | 42.31% | 61.32% | 50.07% |
| 平稳 | 48.16% | 35.47% | 40.86% |

在这一份单日数据上，简单因果模型确实优于 DeepLOB。保留混合 DeepLOB checkpoint 是为了
后续增加连续交易日后再比较，而当前最佳诊断预测器应使用逻辑回归。

### 10.4 结论边界

这次修复证明了两件事：

1. 盘口恢复正确后，当前及过去盘口中确实存在明显高于恒定/随机基线的分类信号；
2. 单日约4.3万个高度重叠开发样本仍不足以让完整 DeepLOB 稳定胜过25维线性模型，神经网络
   的容量远大于当前有效独立样本量。

但最终后30%在初版实验中已经看过，因此改进实验属于迭代 holdout，而不是完全未见的新测试。

| 严格跨日测试 | 非重叠交易数 | 点差后平均/笔 | 再扣5.54bp后平均/笔 |
|---|---:|---:|---:|

未计任何额外费用时已经全部为负，长短双向和只做多都得到相同方向的结论；把预测概率阈值

根因是标准 DeepLOB 标签
`future_mean(mid, 20) / past_mean(mid, 20) - 1` 奖励“未来均价相对过去均价”的方向，
但交易在当前信号之后才进场。模型可能正确识别价格相对过去均价的位置，却无法保证从

### 11.5 PnL 对齐标签仍未形成盈利策略

为排除标签错配，又把训练目标改为三种可执行动作：

- 若下一快照做多并在 `h` 档后退出，扣点差和5.54bp后为正，标为做多；
- 若做空净收益更高且为正，标为做空；
- 两者都不能覆盖成本时标为空仓。

测试 `h=20/50/100`。自然类别权重模型学到的大多是空仓；强制类别平衡会增加交易，但主结果
仍为负。所有至少10笔的候选中，最好的是 **07-09→07-21、h=50、只做多、概率≥0.5**：
仅11笔，点差后 +5.45bp/笔，再扣5.54bp后 **−0.09bp/笔**；它没有在08-07或另一恢复口径
复现。少数只有1笔的组合偶然为正不能作为策略证据。

### 11.6 结论

**当前因果特征逻辑回归不能称为赚钱策略，也不应实盘。** 它确实拥有跨日方向分类信息，
但可兑现幅度小于点差和费用。更高准确率与正 PnL 在这里是两个不同目标。

若继续推进，优先级应是：

1. 收集至少数周连续交易日，并预留从未参与任何选择的完整最终测试周；
2. 用可执行净收益或挂单成交概率直接定义目标，而不是继续优化标准三分类 Accuracy；
3. 保留逐事件时间或固定毫秒时间，避免“每10个变化组”导致不恒定的持有时长；
4. 加入排队位置、可成交数量、冲击、延迟、最低佣金、融券费和无法融券情形；
5. 只在验证日选择 horizon、概率阈值和持仓规则，再按完整交易日做 walk-forward；
6. 用日级或区块 bootstrap 判断收益是否稳定，不能把高度重叠窗口当独立样本。

## 12. 用方向预测增强 AS / GP 做市

### 12.1 为什么不是“预测涨跌后直接买卖”

这里的 GP 指 **Guilbaud–Pham**。经典 Avellaneda–Stoikov（AS）以扩散中价、库存风险和
随报价距离变化的成交强度求最优买卖价；Guilbaud–Pham（GP）进一步把 tick、随机点差、
限价单成交和必要时用市价单处置库存纳入离散控制。原始论文：
[Avellaneda–Stoikov (2008)](https://math.nyu.edu/inmemoriam/avellaneda/HighFrequencyTrading.pdf)、
[Guilbaud–Pham (2013)](https://arxiv.org/abs/1106.5040)。Guilbaud–Pham 后续也明确讨论了
[带预测方向信息的高频交易](https://arxiv.org/abs/1205.3051)。

本实现不把分类结果当成吃单指令，而把它作为保留价的条件漂移：

```text
score_t = p(up | LOB_t) - p(down | LOB_t)
expected_move_ticks_t = validation_calibrator(score_t)
reservation_center_t
  = mid_t
  + signal_strength * expected_move_ticks_t * tick
  - inventory_skew * (q_t / q_max) * tick
```

方向向上时买价更积极、卖价更保守；方向向下时反向。多头库存会把整个报价中心下移，促使
卖出并抑制继续买入；空头库存反向。所有报价取整到0.02 HKD tick，并保证买价低于卖价。
达到 `q_max` 后停止增加同方向库存，测试结束用一档价平仓。

准确率没有直接写进 PnL 公式。`p(up)-p(down)` 只在更早验证期拟合到未来20档中价变化；
若非零信号在保守 through 成交模型下的验证目标不能胜过无信号基线，alpha 自动关闭。
07-09 验证通过，所以07-21启用；07-21验证未通过（风险调整目标低91.89 HKD等价），所以
08-07关闭。这是事前 kill switch，不是看完测试收益后的选择。

### 12.2 成交和费用假设

每20个采样快照撤单重挂一次，每次100股，假设5 ms 下单延迟。成交只由报价之后的原始
`MsgType=50` 成交打印触发，并给出两个无法再收窄的队列情景：

- `touch`：后续成交价到达挂单价就认为成交。这忽略前方队列，是乐观上界；
- `through`：后续成交价至少穿过挂单价一档才认为成交。这是更保守的队列代理；
- 同一报价区间每边最多成交一次；库存始终受硬上限约束；
- 费用分别报告零费用毛收益、仅官方固定1.27bp/边、以及再加假设佣金1.50bp/边后的
  2.77bp/边结果；未假设 maker rebate。

原始数据没有“本策略虚拟订单”的真实队列位置，也没有订单确认回报，因此 touch/through
不是精确交易所重放。可靠结论必须优先看 through；touch 只能说明在较好的排队位置下的潜力。

### 12.3 两次严格 walk-forward 结果

| 测试日 | 分类 Accuracy | alpha | 成交情景 | 传统基线净 PnL | 方向增强净 PnL | 增量 |
|---|---:|---|---|---:|---:|---:|
| 2026-07-21 | 58.85% | 启用 | through | −3,254.49 | **−1,164.54** | **+2,089.95** |
| 2026-07-21 | 58.85% | 启用 | touch | −2,175.32 | **−235.15** | **+1,940.17** |
| 2026-08-07 | 58.48% | 验证未过，关闭 | through | −572.63 | −572.63 | 0.00 |
| 2026-08-07 | 58.48% | 验证未过，关闭 | touch | **+417.06** | **+417.06** | 0.00 |

单位为 HKD，均按2.77bp/边费用且日末平仓。07-21 的非零 alpha 在两种排队情景下都显著
降低了亏损，也同时优于“使用相同方向模型参数但强制信号为0”的配对消融；但它仍没有在
含佣金后变成正收益。08-07 的事前开关关闭了弱 alpha，因此没有为了追求预测使用率而承担
额外风险。

两天合计：

| 成交情景 | 策略 | 零费用毛 PnL | 仅官方固定费后 | 含假设佣金后 | 盈利天数 |
|---|---|---:|---:|---:|---:|
| through | 传统基线 | −776.00 | −2,174.89 | −3,827.12 | 0/2 |
| through | **方向增强+开关** | **+226.00** | **−674.08** | **−1,737.17** | 0/2 |
| touch | 传统基线 | +3,468.00 | +1,071.84 | −1,758.26 | 1/2 |
| touch | **方向增强+开关** | **+3,522.00** | **+1,990.62** | **+181.90** | 1/2 |

touch 下含假设佣金两天合计为正，但数值小、只有1/2天盈利，而且 touch 本身是乐观排队
上界；through 下方向信息把毛收益从负变正，却仍不足以覆盖官方固定费用。因此当前最准确
的表述是：**方向预测有降低逆向选择的增量价值，但尚未证明是可赚钱的做市策略。**

另外，两个验证期中 `score` 与未来实际 tick 变化的相关只有0.040和0.015。这说明约60%的
三分类准确率有一部分来自对很小价格变化的正确分类，并不等于每次具有足以覆盖交易成本的
经济幅度。alpha 校准和 kill switch 是这个模型不可删除的组成，而不是保守装饰。

### 12.4 验证状态与下一步

独立脚本复核了16,565条模拟成交，费用、因果时序、每边每区间最多一次成交、库存上限、
分组计数、汇总结果、训练日在测试日前以及三天 MBO 状态未污染共10项检查，全部通过。
整体评估为 **Share with caveats**，主要 caveat 仍是队列位置不可观测。

下一阶段应先获得更多连续日和真实账户被动费率，再冻结如下规则：

1. 保留 alpha 经济校准和验证期开关，禁止仅凭 Accuracy 强制启用；
2. 从固定快照周期改为固定毫秒撤挂，并加入订单确认/撤单延迟；
3. 若能取得逐订单队列回报，用 queue-ahead 数量替代 touch/through 上下界；
4. 分开估计各点差状态、时段和方向下的成交强度与 markout，直接优化净 maker edge；
5. 至少用数周 walk-forward 和完全冻结的最终测试周评估日级收益、回撤与稳定性。

## 13. 方向增强的秒级 markout、双侧逆向选择与配对 PnL

### 13.1 本轮回答的问题

上一节的 alpha kill switch 同时混合了分类、PnL和回撤。本轮不再先问“是否启用”，而是固定
测试方向增强本身，并回答四个更直接的问题：

1. 模拟成交后5、10、20秒，中价向有利还是不利方向移动；
2. 做市买单和卖单各自承担多少 adverse-selection cost；
3. 同一天、同一组基础报价参数下，方向报价相对 `signal_strength=0` 的配对增量 PnL 是多少。
4. 完整的“方向+库存”模型，相对独立调参的经典 AS 和 GP-style 库存基准是否更好。

第二阶段参数选择不再只依赖07-21。MBO 链合并07-09后30%和07-21整日样本外预测；MBP
链合并07-21后30%和07-22整日样本外预测。两条恢复口径仍完全分开。

### 13.2 名词解释和符号

**Markout** 是“成交后回头评价成交质量”。设做市商买入的方向符号为 `+1`，卖出为 `−1`：

```text
execution_markout(h)
  = maker_side * (mid[t+h] - execution_price) / execution_price
```

买入后价格上涨、卖出后价格下跌时 markout 为正。它包含挂在 bid/ask 获得的价差。

**Adverse-selection cost（逆向选择成本）** 只看成交后中价移动，不包含成交价相对中价的
半个价差：

```text
adverse_cost(h)
  = -maker_side * (mid[t+h] - mid[t]) / mid[t]
```

买单成交后价格下跌、卖单成交后价格上涨时该值为正，表示做市商刚成交就被市场向不利方向
移动；数值越低越好。本文的 `adverse_cost_reduction = no_signal_cost - directional_cost`，
所以正值表示方向增强降低了逆向选择。

**配对增量 PnL** 是方向策略 PnL 减去无信号策略 PnL。两者使用相同测试日、基础挂单距离、
库存惩罚、库存上限、撤挂周期和费用，唯一强制差异是无信号策略的 `signal_strength=0`。
库存路径和实际成交集合可以因方向报价而分化，因此它是策略级配对，不是逐笔一一配对。

**Touch / through** 仍分别代表“成交价触及即成交”的乐观队列情景和“至少穿过一档才成交”
的保守情景。核心判断优先使用 through。

主基准中的三个模型使用相同验证期、费用、延迟、撤挂周期和候选库存上限，各自在验证期
最大化 `净 PnL − 0.25 × 最大回撤`。经典 AS 的20快照方差和指数成交衰减参数只从验证期
估计。GP 基准是包含离散 tick、库存偏移、硬库存上限和日末平仓的 **GP-style 近似**，不是
Guilbaud–Pham 原论文 QVI 的完整数值解。

全部数字已计每边2.77bp费用并日末平仓：

| MBO | 07-21 | touch | −235.15 | **+516.16** | −2,175.32 | −751.31 | +1,940.17 |

| MBO | 08-07 | touch | **+1,448.72** | +367.08 | +417.06 | +1,081.65 | +1,031.67 |
| MBP | 07-22 | through | −5,526.06 | −5,551.15 | **−5,289.69** | +25.09 | −236.37 |

调参后再做模型级比较。

### 13.5 “更多连续验证日”的实际边界

当前公平对比使用的 MBO 滚动链为07-09、07-21、08-07，三者不连续。07-22与07-21相邻，
但07-22在本实验中走 MBP/NPZ。NPZ保留了158,784条买卖侧 execution events，因此本轮使用独立的
07-21→07-22→08-07 MBP 链；没有把它混入 MBO。

这比“只让07-21决定08-07”更稳健，但仍只有两个验证区间和一对相邻日，远少于数周连续
数据。要真正完成用户提出的连续验证，需要继续上传至少10–20个连续交易日的同一 MBO
事件格式；届时固定滚动窗口，例如“过去5天校准和选参，下一天只测试”。
